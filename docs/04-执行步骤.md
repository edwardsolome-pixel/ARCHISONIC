## 1. 工作原则

1. 一次只推进一个功能/里程碑，验收通过才进下一个；不过度开发
2. 每步产出可运行、可验收的版本；验收 = 在浏览器按本节标准逐项走查
3. 每次改动完成：更新 DEVLOG.md → git 提交（提交信息简明描述内容，推荐
   `feat: ...` / `fix: ...` / `docs: ...` / `ui: ...`；里程碑节点可用 `M{n}: ...`；
   git 位于 E:\Git，调用一律用完整路径 `E:\Git\cmd\git.exe`）
4. 向用户汇报实际验收结果（含失败项），由用户确认后才进入下一步

## 3. 会话工作流程（每次开发会话）

1. 读 CLAUDE.md → 按当前任务读 docs/01、02、03 对应部分
2. 只做当前任务范围内的事
3. 完成或告一段落：按验收标准自检 → 向用户汇报实际结果
4. 会话结束前：更新 DEVLOG.md 当日分节（完成 / 待办 / 下一步）
5. 功能/里程碑验收通过：git 提交（信息格式见 §1.3）

## 4. 全程约束自查（每次改动都查）

- [ ] 无网络请求（DevTools → Network 应为空；唯一允许的媒体请求是本地 OST 文件）
- [ ] file:// 双击直接可用（不依赖本地服务器）
- [ ] 无外部依赖（无 CDN / 在线 webfont / npm / ES Module）
- [ ] 字体使用内置 fonts.css（IPix），不依赖系统安装
- [ ] 界面文案以英文为主；中文仅限用户指定标签（古典主义/现代主义、键盘/鼓、构件、门/窗）
- [ ] 代码注释中文
